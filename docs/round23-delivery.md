## 一、换掉三个嫌疑（按可能性排序）

### 1. PiP 窗口的渲染载体：SurfaceView → **TextureView**（最大嫌疑）

`SurfaceView` 是"在窗口上打洞 + 独立图层"。进 PiP 的那段动画里，窗口会被系统反复
resize / reparent，**它的 surface 会被销毁并重建**：每次销毁我们都必须阻塞主线程等
Dart 把 mpv 摘下来（画面变黑），重建后再挂回去（画面回来）—— 这正是"画面与黑屏
来回闪烁"的形状。

`TextureView` 的 `SurfaceTexture` 只在 view 被移除时才销毁，窗口动画/缩放期间一直有效
（尺寸变化只走 `onSurfaceTextureSizeChanged`，我们跟着 `setDefaultBufferSize` 即可，
`wid` 不变、不需要重新交接）。而且 **SurfaceTexture 包出来的 Surface 正是 media_kit
喂给这个定制 libmpv 的同一种东西**（Flutter 那边也是 SurfaceTexture），所以这条渲染
路径是已经被验证过的，不是我新发明的组合。

顺带对齐 media_kit 的做法：缓冲尺寸按**窗口大小**设（小窗不需要片源那么大的缓冲），
并把 mpv 的 `android-surface-size` 一并设成窗口大小（上一轮传的是 `0x0`）；
交还 Flutter 纹理时把原值还原回去。

### 2. 主 Activity 的"自动画中画"提前关

上一轮 `_suppressHostAutoPip()` 是在**交接完成之后**才调的。于是启动 `PipActivity`
让主 Activity 退到后台的那一瞬间，它可能已经按「后台画中画」设置把自己也缩成了一个
小窗 ⇒ 屏幕上两个 PiP 互相抢焦点（也会表现为画面/黑屏来回切）。
现在它和"退出全屏"一起挪到了 `SystemPipBridge.start()` **之前**。

> 如果你开着「设置 → 播放设置 → 后台画中画」，这条尤其相关。

### 3. 排障可见性 + 自检兜底

- PiP 期间把 **mpv 自己的 error/fatal 日志**转进应用日志（`[pip][mpv][vo] ...`），
  交接后打印 `current-vo`。下次再有问题，日志里会直接写清楚是 EGL surface 建不起来、
  还是 wid 无效、还是 vo 初始化失败 —— 不用再靠猜。
- 自检（2.6 秒，三次 wid 补刀都跑完之后）从"只看 wid / 播放状态"升级为三段式：
  1. `wid` 不在 PiP 窗口手里 **或 `current-vo` 为空**（vo 根本没起来 = 窗口必然黑）
     → **自动退回应用内浮窗**；
  2. 只是被"退后台就暂停"停掉 → 先补一次 `play()`，1 秒后复查，仍暂停才退回浮窗；
  3. 都正常 → 什么都不做。
  退回浮窗时会 toast 告知，并提示可以在设置里换实现。

## 二、新增设置：画中画样式（用户侧自救开关）

「设置 → 播放设置 → **画中画样式**」（`PipStyle`，持久化 index，只追加不改序）：

| 选项 | 行为 | 适用 |
|---|---|---|
| **系统画中画（独立窗口，可继续浏览应用）**（默认） | `PipActivity` + mpv `--wid` 交接：系统级小窗（可出应用、可拖动缩放、有系统媒体按钮），主界面照常可点 | 想要真·系统 PiP |
| **应用内浮窗（不出应用，兼容性最好）** | 纯 Flutter 的 root Overlay 小窗，**不碰 mpv 的渲染目标**，不依赖 ROM 的窗口/surface 行为 | 系统 PiP 在这台设备上不稳时的稳妥选择 |
| **系统画中画（整个应用，老行为）** | 上游 PiliPlus 的做法：收起的是整个应用，PiP 期间不能在应用内浏览，但可以出应用 | 只想要"离开应用还能看" |

顶栏画中画按钮：**点按**走所选样式（选"系统独立窗口"而失败时仍依次退回
整应用 PiP → 应用内浮窗）；**长按**始终是应用内浮窗。按钮 tooltip 会显示当前样式。

## 如果这版系统 PiP 还是不行

那就说明这台 ROM 上"把 mpv 的渲染目标搬到另一个 Activity 的 surface"这条路走不通
（日志会告诉我们卡在哪一步）。届时有两个务实选择：

1. **把默认样式改成「应用内浮窗」**（一行改动）：它是纯 Flutter 的，不碰渲染目标，
   兼容性最好；代价是出不了应用（离开应用就没有小窗）。
2. 走**双引擎**（`FlutterEngineGroup`）：PiP 窗口里是真正的 Flutter 播放页且应用可浏览，
   但第二个 isolate 不能与主 isolate 同时打开同一 Hive 盒子 ⇒ 存储层要改成
   "主 isolate 持有 + 消息传递"，还要第二个 mpv 实例、进 PiP 时重新起播、
   两套播放状态同步。多轮工程量的重构，详见 `docs/round21-delivery.md` §5。
