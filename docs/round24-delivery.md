# 第二十四轮：按"整个播放页进画中画"的设计意图纠正实现

## 一、你说得对的部分，与一条绕不过去的平台约束

你的路线是：**整个播放页作为一个独立 Activity**，进 PiP 时收起的就是这个 Activity
（= 播放页），主应用不受影响 —— 这正是 moonlight-android 的结构（串流在独立的
`Game` Activity，浏览界面是 `PcView`）。

我上一轮的实现（进 PiP 时才新开一个 native Activity，把 mpv 的渲染目标 `--wid`
交接过去）确实**偏离了这个结构**：PiP 窗口里只有 mpv 直出的画面，没有 Flutter
播放页那一层（控件/弹幕/VR 层）。这一点你指出得对。

但有一条 Flutter 平台硬约束决定了"独立播放页 Activity"与"PiP 期间还能在应用内浏览"
**在单引擎下不能同时成立**：

> **一个 FlutterEngine 同一时刻只渲染一个 Activity。**
> `FlutterEngineConnectionRegistry.attachToActivity()`（Flutter 引擎源码
> `shell/platform/android/io/flutter/embedding/engine/FlutterEngineConnectionRegistry.java:317`）
> 的行为是：`if (this.exclusiveActivity != null) { this.exclusiveActivity.detachFromFlutterEngine(); }`
> —— 把引擎交给新 Activity 时，**前一个 Activity 会被强制 detach**，它的
> FlutterView 立刻失去渲染表面（变空白）。旧版本这里是直接抛
> `IllegalStateException("Already attached to an activity")`，新版本改成强制 detach，
> 但"独占"这件事没变。

推论：

| 你想要的 | 引擎在哪 | 结果 |
|---|---|---|
| PiP 窗口里是**整个 Flutter 播放页** | 引擎必须在**进 PiP 的那个 Activity** 上 | 主 Activity 没有引擎 ⇒ 空白，**PiP 期间不能在应用内浏览** |
| PiP 期间**还能在应用内浏览** | 引擎必须留在**主 Activity** | PiP 窗口只能由 native 渲染画面（我上一轮的做法），窗口里没有 Flutter 播放页 |
| 两者都要 | 需要**两个引擎** | 见下面第三节 |

所以"整个播放页进 PiP"在单引擎下的等价实现，就是**让持有引擎的那个 Activity 自己进
系统 PiP**：应用在 PiP 模式下本来就只渲染播放页（`pages/video/view.dart` 里
`if (plPlayerController.isPipMode) child = plPlayer(..., isPipMode: true)`），
所以窗口里出现的**就是整个播放页**（控件、弹幕、VR 层都在），而且**完全没有
surface 交接** —— 这也顺带绕开了你这几轮遇到的黑屏/闪烁/闪退那一整类问题
（那条链路是上游 PiliPlus 一直在用的，最稳）。

## 二、本轮改动

1. **默认画中画样式改为「系统画中画·整个播放页」**（`PipStyle.systemWholeApp`）。
   顶栏画中画按钮**点按**即走这条路：主 Activity 进系统 PiP，窗口里是整个播放页，
   无 `--wid` 交接、无第二个 Activity、无 surface 生命周期问题。
2. 三种样式的文案改成**把取舍写在脸上**（设置 → 播放设置 → 画中画样式）：
   - `系统画中画·整个播放页（最稳，不能同时浏览）` ← **新默认**
   - `系统画中画·独立窗口（可同时浏览应用）` ← 上一轮那条 native 交接链路
     （r23 已改 TextureView + 交接自检兜底，失败会自动退回应用内浮窗）
   - `应用内浮窗（可同时浏览，不出应用）` ← 纯 Flutter，不碰渲染目标
   枚举顺序**未变**（持久化的是 index），只改 label 与默认值；已经手动选过的人
   保持自己的选择。
3. 顶栏按钮 tooltip 显示当前样式与设置入口；**长按**始终是应用内浮窗（兜底）。

### 这条默认路径的行为（请照这个预期测）

- 点画中画 → 整个应用缩进系统 PiP 窗口，窗口里就是播放页（画面 + 控件，
  弹幕按「画中画不加载弹幕」设置决定）。
- 点窗口 → 系统控件条：展开（回到应用全屏播放页）/ 关闭 / 系统媒体按钮
  （快退、播放暂停、快进）。
- 点**展开** → 回到应用，播放页原样还在，进度不丢（播放器全程没动过）。
- 点**叉号** → **连同应用一起退出**（这是系统对"整应用 PiP"的标准行为：
  关掉的就是那个 Activity，而它承载着整个应用）。要"只关视频不关应用"，
  请选另外两种样式。
- 按 Home（且开了「后台画中画」）→ 同样是这套整应用 PiP。
- **PiP 期间不能在应用内浏览**（单引擎约束，见上表）。要浏览就用
  「独立窗口」或「应用内浮窗」，或长按画中画按钮。

## 三、如果你要"窗口里是 Flutter 播放页"且"同时能浏览应用"

只能上**第二个引擎**（`FlutterEngineGroup` spawn 一个 isolate 跑 PiP 里的播放界面）。
必须提前说清的代价与边界：

- 第二个 isolate **不能与主 isolate 同时打开同一个 Hive 盒子**（同进程两个 isolate
  打开同一 box 文件会互相覆盖/损坏）⇒ 存储层要改成"主 isolate 持有 + 消息传递"，
  或者 PiP isolate 完全不碰存储（启动时把需要的设置一次性快照传过去）。
- PiP 里跑的是**另一个 Player 实例**：进 PiP 时视频要在第二个 isolate 里重新起播
  （本地文件 <1 秒；在线视频可以把已解析好的播放地址传过去，省掉重新请求，
  但仍要重新缓冲 ~1 秒），退出 PiP 再把位置同步回来。
- 内存/CPU：第二个引擎（spawn 约 +40~60MB）+ 第二个 mpv 实例（约 +30~80MB）。
- PiP 里能有什么：视频画面 + 一套**精简**播放控件（播放/暂停、进度、字幕轨、
  倍速、关闭/展开）。**弹幕、评论、相关视频这些依赖主 isolate 状态的部分不会有**
  ——除非把数据也序列化传过去（弹幕数据量大，不划算）。
- 工作量：Kotlin（FlutterEngineGroup、PiP FlutterActivity、通道协议）+ Dart
  （独立 entrypoint、精简播放页、状态同步）约 600~900 行，且我在沙盒里只能验证
  编译，运行时行为要靠你真机测。

**要做的话请明确一句"上双引擎"**，我就按上面这个边界开工（会先把存储层改造单独
拆一轮，避免和播放逻辑混在一起）。
