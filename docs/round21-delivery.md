## 1. DS 手柄 × 键 = 播放/暂停（全屏时）

- 安卓把 PS 手柄的 **×** 报成 `KEYCODE_BUTTON_A`，Flutter 侧是
  `LogicalKeyboardKey.gameButtonA`（Xbox 手柄的 A 是同一个键位）。
- **仅全屏时**生效，动作与空格键、双击画面中间完全一致
  （`onDoubleTapCenter()`，带播放/暂停的浮层反馈）。
- 非全屏**不吃**这个键：让它继续走系统焦点，否则页面里的按钮没法用手柄确认。
- 只认 `KeyDownEvent`（长按的 `KeyRepeatEvent` 不会反复切换）。
- 提醒：○（`KEYCODE_BUTTON_B`）在 `MainActivity.dispatchKeyEvent` 里已被映射成
  "返回"（既有行为，本轮未动）；START/MODE 仍是"退到后台"。

## 2. 记忆播放里加上字幕

`LocalMediaSettings` 新增 `subtitleId` / `subtitleTitle`：

- **存什么**：mpv **实际生效**的那条轨（`currentTrack.value.subtitle`）——
  字幕面板上显示什么就记什么；播放器刚起、还没选好轨时 id 为空，这时不写
  （保持默认策略，不产生"记住一个空值"）。
- **怎么恢复**：优先按**标题**找（外置字幕的标题就是文件名，比轨道号稳 ——
  轨道号会随内嵌轨数量漂移），找不到再按轨道号；都找不到就**什么都不做**，
  宁可回到默认策略也不要因为记错而没字幕。`'no'`（关闭）与 `'auto'` 也能记。
- **什么时候恢复**：在同目录外置字幕被 `sub-add` 进 mpv 列表**之后**
  （否则选不中），即 `_autoloadLocalSubtitles()` 完成后。
- 落盘节奏与其它记忆项一致：播放中每 5 秒 + 切集前 + 退出播放页。
- 范围仍是**本地 / 局域网媒体**（在线视频的字幕是 B 站 CC，走另一套索引）。

## 3. revert：手柄按键长按连续输入（上一轮需求 3）

按你的要求整块回退：

- 移除 `startKeyRepeat` / `stopKeyRepeat`（含 400ms 延迟 + 110ms 连发定时器）；
- 移除 VR 操作模式下"十字键 = 视角步进"，十字键恢复原语义
  （左右快退快进、上下音量），与第十九轮一致；
- 移除眼位切换的 400ms 冷却；
- △/□ 回到"只认 `KeyDownEvent`"（长按产生的 `KeyRepeatEvent` 天然不会重复触发）。

VR 手柄能力保留：右摇杆环视、△ 摆正、□ 切眼位、且不唤起播放器 UI。

## 4. 摇杆/拖拽不再跳变：逐帧插值

上一轮把下发节奏从 30ms 节流改成"每帧一次"，解决了**更新率**问题；
但输入本身仍是离散的（触摸事件、摇杆采样都是一格一格），画面角度会跟着跳。
本轮把"输入"与"下发"彻底拆成两个状态：

- `_vrTarget`：**输入目标**。手指拖拽 / 摇杆积分 / 屏幕步进按钮改的都是它。
- `vrView`：**实际下发给 mpv、也是 HUD 显示的**角度。由帧回调每帧朝目标做
  **帧率无关的指数趋近**：`alpha = 1 - e^(-dt/τ)`，`τ = 45ms`
  （60Hz 下约 3 帧走完 63%、~135ms 走完 95%）——小到感觉不出延迟，
  又足以把台阶抹平；60/90/120Hz 手感一致，且永远不会 overshoot。
- 收敛判定 0.01°（下发的 `vr-view` 只保留两位小数，再细也写不出去），
  收敛后**自动停止排帧**（不会白泵帧），并复位计时避免下次 dt 过大。
- **偏航按最短角路径插值**：360° 片源的偏航会不断回绕（…179° → −179°…），
  直接线性插值会在接缝处"倒转一整圈"。新增
  `VrViewState.wrap180` / `VrViewState.shortestDelta`（有单测覆盖语义）。
- **离散动作不插值**（`snap`）：摆正视角、切换片源布局、自动识别结果落地 ——
  否则"按了摆正"还要等几帧才到位。
- **双指缩放的基准改用目标视场角**：用插值中的显示值当基准，连续捏合会
  越捏越慢（基准一直在追自己）。
- 保留上一轮的慢设备保护（单次属性写入 >6ms 自动隔帧）与摇杆
  "采样(≈100Hz)/积分(每帧)解耦"；帧 Ticker 改为**只在摇杆偏出死区时**才跑
  （暂停播放时不再白白泵帧）。

与陀螺仪仍有的差别（不变）：陀螺仪在 libmpv native 侧逐帧跑且有 33ms 前视**预测**，
手动输入没有预测、且每帧要过一次 Dart→FFI 属性写入。要完全同级需给 libmpv 补丁加
`vr-look-velocity`（deg/s）在逐帧的 `vr_manual_angles()` 里积分（见 round20 文档）。

## 5. "播放页作为独立 Activity 实现 PiP" —— 需要你先定方向

**moonlight 为什么可以**：系统 PiP 收起的是"调用 `enterPictureInPictureMode()`
的那个 Activity"。moonlight 的串流跑在独立的 `Game` Activity（native 渲染），
浏览界面是另一个 Activity（`PcView`/`AppView`）；`Game` 进 PiP 后它的任务被移到
pinned 栈，主任务照常回前台 ⇒ 边 PiP 边浏览。

**Flutter 的硬约束**：一个 `FlutterEngine` 同一时刻只能附在**一个** Activity 的
FlutterView 上（`FlutterEngineConnectionRegistry.attachToActivity` 第二次调用直接抛
`IllegalStateException: Already attached to an activity`）。所以"把 Flutter 播放页
放进独立 Activity"只有三条路：

| 方案 | PiP 窗口里是什么 | 应用内能否继续浏览 | 代价/风险 |
|---|---|---|---|
| **A（当前实现）** 独立 native `PipActivity` + mpv `--wid` 交接到它的 SurfaceView | 纯视频画面（**含 mpv 渲染的字幕**）+ 系统媒体按钮（快退/播放暂停/快进）+ 标题（Android 13+） | ✅ 能 | 已落地、已 CI 通过；PiP 窗口里**没有** Flutter 那层控件与弹幕 |
| **B** 引擎跟着播放页搬到独立 Activity，PiP 时再把 `--wid` 交给该 Activity 的 SurfaceView、引擎搬回主 Activity | 与 A 相同（PiP 期间引擎已搬回主 Activity，Flutter UI 不在 PiP 窗口里） | ✅ 能 | 每次开/关视频都要做一次引擎搬移（黑帧闪烁、生命周期竞态），**PiP 表现与 A 完全一样**，纯粹多担风险 |
| **B'** 引擎留在 PiP Activity（不搬回） | ✅ 完整 Flutter 播放页（控件/弹幕/VR 层都在） | ❌ **不能**（主 Activity 没有引擎，界面是空的） | 与第十九轮"PiP 时还能在应用内浏览"的硬要求冲突 |
| **C** 双引擎（`FlutterEngineGroup` spawn 第二个 isolate 跑播放页） | ✅ 完整 Flutter 播放页 | ✅ 能 | 大重构：第二个 isolate 里 **Hive 盒子不能与主 isolate 同时打开**（同进程两个 isolate 打开同一 box 会互相覆盖/损坏）⇒ 存储层要改成"主 isolate 持有 + 消息传递"；第二个 mpv 实例（内存/CPU 翻倍）；进 PiP 时视频要在第二个 isolate 里**重新起播**（重新拉流+缓冲）；进度/历史/弹幕/字幕两套状态要同步。多轮工程量，沙盒内无法验证 |

我的判断：**A 已经是"用独立 Activity 实现 PiP"**（`PipActivity` 就是独立任务的
native Activity，moonlight 的 `Game` 也是 native 渲染），差别只在"PiP 窗口里
渲染的是 Flutter 播放页还是 mpv 画面"。在单引擎前提下，"PiP 里有 Flutter 播放页 UI"
与"应用内可继续浏览"**不可兼得**；要兼得只有 C（双引擎 + 存储层重构）。

**可选的小增量**（不改架构）：在 `PipActivity` 的 SurfaceView 上用 native 画一层
轻量控件（播放/暂停、展开、关闭、细进度条、标题），让 PiP 窗口更像"播放页"
而不是裸视频。成本低，但小窗里系统本身已经提供了一套控件，可能显得重复。

- [ ] 双指连续捏合缩放：缩放速度均匀，**不会越捏越慢**
- [ ] 按"视角摆正"/切换片源布局：**立即**到位（这两类是离散动作，不做插值）
- [ ] 60Hz 与 90/120Hz 设备（若都有）：转速手感一致
- [ ] 暂停播放时拖拽环视：仍然平滑（帧回调会自己申请帧）
- [ ] HUD 读数（顶部偏航/俯仰/视场）与画面一致、跟随平滑

- [ ] 连续环视 2~3 分钟：不掉帧、不发热加剧、不卡顿（每帧只写 1 个合并属性；
